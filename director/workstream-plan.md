## Workload and coordination targets

- **Director/control plane:** OpenAI continuously owns intake, planning,
  decomposition, neutral coordination, routing, evidence synthesis, recovery,
  acceptance review, milestone reporting, and bounded escalation. This is not
  direct production and is not included in the percentages.
- **Direct production:** Claude 60%, Cursor 28%, Gemini/Antigravity 7%,
  Perplexity 4%, and separately owner-authorized external OpenAI/Codex 1%.
- **External OpenAI production:** Inactive. The Director must never emit itself
  as a specialist target; any 1% external candidate requires owner authorization
  outside this runtime and different-provider exact-candidate review.
- **Capacity:** 95% productive coordination, 5% reserve for checks, drift,
  evidence gaps, recovery, process failures, and infrastructure variance.
- **Commit quality:** Reduce avoidable micro/fixup commits by at least 33% from
  a rolling comparable baseline without combining unrelated risk or weakening
  exact-candidate evidence.

These targets are routing guidance, not permissions, voting weights, guaranteed
provider usage, or a reason to create low-value work. No direct-production
provider has been dispatched in this bootstrap phase.

an overflow-only lane: it has a 90% capability-parity target and eligibility
across all eight areas. Antigravity ordinary work receives no task prose or
repository context. An owner/Director-invited debate may use only an approved
exact payload containing public, non-private, abstract framing; it remains
bounded and grants no operational authority. Perplexity receives only an
approved public query and must preserve
query/source/date/excerpt/type/confidence/contradiction/gap provenance.

## D1/G1 control-plane packet

- **Starting state:** The concept, critique, private repository, branch, worktree,
  coordination surface, and zero-dollar phase budget are established.
- **Target outcome:** One bounded prototype specification with explicit state,
  interaction, host/dealer, and rights requirements.
- **Scope:** Project documents in the confirmed private repository; no mutation
  of `sources/`.
- **Provider:** OpenAI Director for framing, routing, and acceptance synthesis;
  never as a specialist assignment target.
- **Authority granted:** Create and revise project-local planning artifacts.
- **Authority denied:** Paid provider launches, Slack posts, uploads, deployment,
  publication, purchases, credential changes, or licensing commitments.
- **Acceptance checks:** Deterministic rule transitions; clear card-commit UX;
  server-authoritative concealed state; complete dealer/host permission matrix;
  rights-clean audio paths; accessibility coverage.
- **Evidence required:** Scenario tables, state transitions, role matrix, and
  explicitly marked unknowns.
- **Bound:** One strict preset, one room, four seats, optional AI fill, VR plus
  only the MR interactions needed to place and use the same table.
- **Fallback:** Select the smallest local toolchain at G1 instead of exploring
  engines or providers broadly.
- **Handoff target:** Director technical selection at G1, then a bounded producer.

## Coordination sequence

`BOOTSTRAP` -> `PLAN` -> `WORKING` / `EVIDENCE` -> `OWNER_DECISION_REQUIRED`
-> future `REVIEW_READY` -> `COMPLETE`, `PAUSED`, or `RESHAPED`.

1. Keep coordination in this Codex project task; Slack is not required.
2. Verify the exact repository, starting ref, worktree, and branch before any
   local provider assignment.
3. Give one producer ownership of each implementation surface.
4. Use a different eligible provider for exact-candidate review.
5. Any candidate change invalidates earlier review, security, CI, and merge
   evidence.
6. Do not retry an ambiguous paid dispatch; reconcile it first.
7. Select dependency-ready work sequentially; do not infer parallel external
   dispatch from scheduler readiness.
8. Perplexity review feedback requires a newly approved public query rather
   than a silent rerun of the original.

## Completion and runtime overlay

- Provider-chunk acceptance and whole-project completion are separate gates.
- `COMPLETE` requires human user testing and owner acceptance of the unchanged
  exact candidate, regardless of assignment or automated-gate status.
- Merge eligibility is evidence only and performs no merge.
- Director host completion runners, live LangGraph packet handling, live
  provider dispatch, parallel external execution, and regex-based privacy
  filtering are permitted future work. They are not presently enabled; each
  requires its own readiness, evidence, budget, and owner-activation gate.

## Owner and deterministic gates

- Director selection of the smallest engine/toolchain justified by the accepted
  prototype specification; repository, branch, worktree, and $0 provider budget
  are already confirmed.
- Server-authoritative deck and concealed-information boundary.
- Focused deterministic rules and interaction tests.
- Rights review before shared host-supplied music or archival/cultural assets.
- Different-provider exact-candidate review before merge or release.
- Current CI, security/privacy, and asset-provenance evidence when applicable.
