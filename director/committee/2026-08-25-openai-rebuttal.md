# Rebuttal — OpenAI participant

## Agreements

1. Claude's disconnect/leave precondition closes a real Human Host authority
   gap and should be adopted.
2. “Helpful” concealed-hand visibility must be an explicit prohibited feature,
   not merely inferred from a general privacy rule.
3. A single rules core should drive both stages. A practical path is a pure C#
   domain assembly tested headlessly, used by a Unity WebGL interaction harness
   and the Quest Android/OpenXR build; this avoids cross-language rule drift.

## Disagreements / corrections

1. The AI Dealer need not be silent or limited to legality rejection. It may
   explain deterministic engine outputs, announce turn/phase, teach the named
   manifest, and present timers. The engine—not the model—owns every transition;
   explanatory speech carries no independent authority.
2. “Same engine, unmodified” should mean the same domain assembly, manifests,
   and conformance tests—not identical presentation or platform adapter code.
   WebGL and Quest necessarily have different input, avatar, audio, and session
   adapters.
3. Safety controls must precede any external social playtest, but rules and
   private local device testing can proceed in parallel with that work if no
   unprotected participant is exposed.

## Vote

`RESHAPE` — unchanged. The rebuttal strengthens the authority matrix and points
to one shared Unity/C# core as the cleanest way to make the paired proof real.
