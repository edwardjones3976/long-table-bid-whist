# The Long Table — neutral cross-position digest

**Phase:** rebuttal input  
**Raw provider transcripts:** not forwarded  
**Authority:** none

## Agreement

Every completed seat agrees on the following:

1. A Horizon World should not be the authoritative flagship on current evidence.
2. The flagship interaction belongs in a native Quest app unless a physical-device spike invalidates the premise.
3. Optical hands should carry the emotional “this is real” moment; Touch controllers must retain precision, haptics, accessibility, and reliability parity.
4. Card physics is presentation. Shuffle, hand ownership, bidding, legality, trick winner, score, reconnect, and host permissions require one deterministic authority.
5. Each client receives its own hand plus a structurally allowlisted public projection. Concealed cards are never transmitted and merely hidden. Regex/blacklist privacy controls remain prohibited.
6. Human players use their own supported Meta character/avatar representation; the only built-in character is a clearly non-human robot dealer.
7. Human hosts may seat, invite, pause, announce, moderate, reconnect, and transfer host authority, but may never inspect hands or alter shuffle, bids, cards, tricks, or score.
8. The experience is seated-first, has no required locomotion, and supports large cards/text, non-color-only suit cues, captions, reduced stimulation, one-hand/one-controller paths, and tracking-loss recovery.
9. Shipped music requires documented composition and recording rights. Host music stays external/private and is not ingested, recorded, cached, synchronized, streamed, analyzed, or rebroadcast.
10. Physical Quest testing, experienced Bid Whist review, target-audience accessibility testing, event-host critique, cultural review, and owner acceptance remain mandatory.

## Central dispute

### Claude and Antigravity: C — staged hybrid

Their strongest case is that the native app remains the sole flagship while existing WebXR work becomes a projection-only companion and a Horizon World is held behind a kill-gated parity spike. This could improve tutorials, host operations, demonstrations, club scheduling, discovery, and return visits without rebuilding the game.

Safeguards proposed:

- one authoritative rules kernel;
- zero net-new gameplay logic on web or Worlds;
- no concealed state on companion surfaces;
- Horizon is not built unless its parity spike passes;
- staged gates prohibit concurrent three-product development.

### Grok: A — native only

Its strongest case is that “staged” is a schedule, not a reduction in surface area. A web companion and a World still create additional design systems, QA obligations, privacy/rights exposure, community fragmentation, and a maintenance tax. The user asked for mind-blowing embodied capability; every non-native lane can consume the resources needed to finish it.

Safeguards proposed:

- keep WebXR internal as a rules harness;
- use native Group Presence, invitations, host tools, teaching table, and observation rail;
- test host-led acquisition before assuming Worlds discovery is necessary;
- only reconsider a non-playable discovery surface if a real hosted-night acquisition test fails.

## Questions for the single rebuttal round

1. Is a strict native-first hybrid genuinely one product with companions, or is it three products disguised as a sequence?
2. What enforceable scope rule prevents the working WebXR companion from absorbing attention while native remains perpetually next?
3. Can native-only host-led acquisition plausibly fill recurring tables for adults 30–70 without a World or external companion?
4. Which companion functions, if any, materially improve hosted nights while introducing zero concealed-state or rights risk?
5. Should a Horizon parity spike test a playable table, or only discovery/deep-link/event boundaries?
6. What concrete evidence would change the provider's vote?

## Rebuttal output contract

Each provider gets one response. It must:

- challenge the strongest opposing argument, not a straw man;
- accept, reject, or narrow the safeguards above;
- identify one non-negotiable kill condition;
- state the evidence that would change its vote;
- end with `VOTE=A`, `VOTE=B`, or `VOTE=C`.
