## Counter-bias challenge

The convergence could still be wrong in five ways:

1. **Toolchain overreach:** a Unity/C# shared core, WebGL harness, Quest build,
   Meta Avatars, controllers, hands, MR, voice, private rooms, moderation, and
   a complete rules engine cannot responsibly be treated as one tiny sprint.
2. **Rules uncertainty:** a technically deterministic implementation can still
   deterministically implement the wrong house rules. The manifest needs
   experienced-player validation before polish.
3. **False demographic confidence:** ages 30–70 and Foundational Black American
   players are not homogeneous. Research supports design hypotheses, not a
   certificate of fit or authenticity.
4. **Shared-core fetish:** literal code reuse is valuable only if it does not
   force brittle platform architecture. “Same core” means the same pure domain
   assembly and conformance vectors, with separate WebGL/Quest adapters.
5. **Event-feature creep:** Human Host, voice moderation, reconnection, music,
   avatars, and social safety can overwhelm the first proof. Their permission
   and state contracts belong in the design now; only the narrowest safe slice
   belongs in the first implementation.

The alternative most likely to beat the chosen direction is a Quest-native-only
vertical slice using placeholder rules. It could generate faster headset
feedback. It loses because it makes rule correctness, hidden information, and
replay harder to isolate, and it invites a visually persuasive but behaviorally
untrustworthy demo.

## Director conclusion: `RESHAPE`

Proceed as a **three-gate milestone**, not a claim of an MVP:

### Gate A — named rules authority

- Freeze `STRICT_TABLE_V1` only after an experienced-player review of its full
  deck, jokers, kitty, auction, high/low/no-trump, follow-suit, trick, Boston,
  scoring, and next-hand behavior.
- Implement one pure C# domain assembly with deterministic seeds, immutable
  transitions, public-seat projections, and replay/conformance vectors.
- The game engine alone advances phases and owns bids, legal actions, tricks,
  score, substitution conditions, and recovery.

### Gate B — paired interaction proof

- A Unity WebGL harness proves the complete deal-to-score task flow and keeps
  iteration easy to observe and test.
- A Quest Android/OpenXR seated slice reuses the domain assembly and proves room
  scale, table calibration, readable cards, controller interaction, and a
  clearly non-human robot dealer.
- User-created Meta avatars are the only human representations. Hand tracking,
  MR placement, networking, spatial voice, and full Avatar SDK presence may be
  separately gated if the first device slice cannot prove them honestly.

### Gate C — safe social foundation

- Define the private session and authoritative reconnection model before live
  multiplayer.
- Before any external social playtest: mute, block, leave, report, host pause,
  and constrained remove/substitute behavior must be present and manually
  verified.
- Cultural-advisor, experienced-player, accessibility, and comfort critique are
  required human gates. A browser or internal device demo cannot replace them.

## Adopted authority matrix

| Capability | Game service | AI Dealer robot | Human Host | Player |
|---|---:|---:|---:|---:|
| Deal, legality, turns, tricks, score | owns | presents only | no | submits actions |
| View a player's concealed hand | legal projection only | no privileged view | never | own hand only |
| Explain rules/announce phase | source of truth | yes, from deterministic state | may clarify socially | may ask |
| Invite and seat | validates session | no | yes | accept/decline |
| Mute/block/leave/report | enforces state | no | host-scoped controls | self-scoped controls |
| Pause | deterministic transition | may announce | may request/trigger within policy | may request |
| Remove/substitute | between-hand transition only | AI seat after valid trigger | only after disconnect/leave or conduct action | may leave |
| Change committed bid/card/trick/score | never outside rules transition | never | never | never |
| Select room ambience | validates allowed configuration | no | rights-safe controls only | local volume |

## Music conclusion

- Prototype music defaults **off**.
- Bundled ambience is allowed only with a provenance record for both composition
  and recording: original commissioned work, verified CC0 dedication, verified
  public-domain composition and recording, or an explicit license covering the
  intended product use.
- A host may later use an external/private playback surface, but file format is
  irrelevant to rights. The game must not represent that media as cleared,
  ingest or redistribute it, include it in recordings, or make it audible to
  others without a separately accepted policy and implementation gate.

## Status of the premature draft

The React/TypeScript room created before this debate is **quarantined reference
material**. It earns zero direct-work credit and is not the selected product
architecture. Providers may inspect its interaction ideas only if a later work
packet explicitly allows that; no implementation assignment may silently adopt
it as the candidate.
