1. What it is and what was built

A card app you play in a browser or a VR headset browser. You enter a room with a name, walk around a 3D mansion and its backyard, sit at one of six card tables (two each of Tonk, Spades and Bid Whist) and play with friends. Rooms hold up to 32 people and are joined by an 8-character code or an invite link. A server decides everything that matters: it shuffles and deals, checks every move, keeps score, and fills any empty seat with a bot once a match starts. Each person sees only their own cards. The 3D world, music and art are all made in code. The older single-player Bid Whist prototype (src/ and the root index.html) is kept and was not changed.

2. Commands from a clean checkout

No secrets, accounts or paid services are used. package.json has no engines field, so no Node version is required by the project. It was verified on Node 26.13.1 and npm 11.20.0.

npm ci

Local development (two terminals)

# terminal 1: the game server, http://localhost:3000
npm run dev:server

# terminal 2: the client, http://localhost:5173 (forwards /socket.io to port 3000)
npm run dev:client

Open http://localhost:5173. The client listens on CLIENT_PORT (default 5173) and stops if that port is busy instead of choosing another. It forwards /socket.io to http://localhost:<PORT> (default 3000), so it follows the server's PORT. In a lane, use the lane commands in workspace.html.

One process, production style

npm run build
npm start

Open http://localhost:3000. npm start runs the same server file (through tsx) and serves the built client/dist folder, falling back to its index.html for unknown paths. The folder is looked up once at start-up, so build first. PORT overrides the port. Note that npm run build also builds the legacy prototype (it runs tsc -b, then the root Vite build, then the client build).

Headset on the same network

npm run dev:server
npm run dev:xr

dev:xr serves the client over https with a self-signed certificate on port 5173, listening on all network addresses. In the headset browser open https://<your PC's LAN IP>:5173 and accept the certificate warning. A headset only allows WebXR on a secure page, which is why https is used. Setting XR_HTTPS=1 with dev:client does the same. Your PC's firewall may need to allow port 5173 (not verified).

Tests

npm run typecheck          # tsc -b
npm test                   # Vitest, all suites (also runs the legacy prototype's suites)
npx playwright install chromium-headless-shell    # once
npm run test:e2e           # builds first, then runs Playwright

test:e2e already runs npm run build itself. Playwright picks a free port, starts server/main.ts on it, runs one worker, and uses software graphics so no GPU is needed. Whether chromium-headless-shell is the exact browser Playwright picks is not set in the config (not verified here; the command is as you gave it).

Server settings

SettingWhat the code does

On every connection the server checks the Origin header. It lets through: no Origin at all (non-browser clients), an Origin whose host matches the request's own host (so the single-process run needs no setting), and anything in the allowed list. Everything else is refused.

3. Architecture overview

The server is the authority. The flow for every game is: the server shuffles and deals, seats players, tracks whose turn it is, offers each player their legal actions, applies only legal actions, and scores. Game rules are pure functions in server/games/; a bad action throws a rule error and changes nothing.

  • Per-recipient views. After any change the server sends each person a snapshot built for them alone. A player gets their own hand and their own legal moves (only when it is their turn). Other hands, the stock order and the Bid Whist kitty and discards never leave the server. The optional host gets the public state only, with no hand.
  • Revision and action ids. Every change raises the match revision. An action names the revision it was based on and carries an actionId (1 to 64 characters). A stale revision is refused. The same id with the same action is answered as a duplicate and not applied twice; the same id with a different action is refused as reused. Actions over 2048 bytes are refused.
  • Reconnect. Joining returns a secret token, kept in the browser tab's sessionStorage. After a dropped connection the client sends it with room:resume and gets the same seat and fresh snapshots. A second connection with the same token takes over from the first. A dropped member's place is held for 60 seconds; after that they are removed and, in a running match, a bot takes the seat. If a room empties it is deleted.
  • Bots. At start, every empty seat becomes a bot, and so does any seat a person later leaves. Bots choose from their own seat's view only, so they cannot see anything a person there could not. They play instantly (no pacing yet) and are simple: they play by rank with no card counting.
  • Automated dealer, optional human host. By default the server deals. A person may instead sit as an optional fifth, non-playing host. The host does not ready up or play, and sets house rules, starts the match, deals the next hand when a hand is over (any seated player can also do this) and resets the table. With no host, that power goes to the longest-seated player. A match starts when every seated player is ready; at least one person must be seated.
  • Rate limit. Each socket may send a burst of 60 acknowledged events, refilled at 20 per second. Over that gets a "rate-limited" reply. Messages are capped at 16 KB.
  • Other limits. Names are 1 to 20 characters. Poses are sent about ten times a second and out-of-range values are dropped. Rooms are in memory only.

4. Default rules and configurable house rules

These are documented defaults, not universal rules. Card games like these are played many ways in different families and regions. The table below is what this app does, chosen so a table can change the common switches. The manager sets them before the match; they are shown to everyone and fixed once play starts. Seats run clockwise and partners sit opposite (seats 1 and 3, 2 and 4) in Spades and Bid Whist; Tonk is every player for themselves.

Tonk (4 players, standard 52-card deck, no jokers)

OptionDefaultAllowed values
Dropping before you draw (knocking)allowedallowed, not allowed
A dealt 49 or 50 wins the hand (initialFifty)yesyes, no
Play to (target)5 points5, 10

Five cards each, one card turned up as the discard pile, the rest is the stock. A turn: draw from the stock or the discard pile (or drop first), then lay melds (sets of 3 or 4 of a rank, runs of 3 or more in one suit, ace low) or add a card to any meld on the table, then discard to end the turn. Card values: ace 1, number cards face value, jack, queen and king 10. Hand scoring in match points:

  • Going out by laying down your last cards: 2. Going out by your final discard: 1.
  • A dealt 49 or 50 (when on): 2 to a lone holder; if two players qualify the deal is void.
  • Drop: 1 if your total is strictly lowest; if not, each lowest opponent gets 2.
  • Stock runs out: 1 to every player tied for the lowest total.
  • First player to reach the target wins (simultaneous finishers share the win).

Variant assumptions made. (a) A card taken from the discard pile cannot be discarded in the same turn. (b) A meld or extension that would leave you holding only that taken card is refused, unless that card fits a meld already on the table, so a legal move always exists. The owner confirmed assumption (b) on 2026-11-18: keep refusing it. (c) The deal is five cards and a drop needs a strictly lower total than every opponent to win.

Spades (2 teams of 2)

OptionDefaultAllowed values
Deck (preset)standard, 52 cardsstandard; jokers (both jokers and the 2 of Diamonds are the top spades, above the 2 of Spades; the 2 of Clubs and 2 of Hearts are removed)
Play to (target)500100, 250, 500
Nil bids (nil)allowedallowed, not allowed (bids then run 1 to 13)
Ten bags cost 100 points (bagPenalty)yesyes, no

13 cards each. Each player bids once, from the left of the dealer; the dealer bids last and leads. Spades cannot be led until broken (unless the leader holds only spades). Players must follow suit if they can. Scoring per team: a made contract is 10 points per trick bid, plus 1 point and 1 bag for each extra trick; a set contract loses 10 per trick bid; a made nil is +100 and a failed nil is -100 (its tricks become bags); if both partners bid nil there is no contract. With bag penalty on, every 10 bags cost 100 points. The game ends when a team is at or past the target with the higher score; a tie at the target plays another hand.

Bid Whist (2 teams of 2, 54 cards with two jokers)

OptionDefaultAllowed values
Lowest bid (minBid)33, 4
A low bid outranks a high bid of the same number (lowOverHigh)nono, yes
A made bid scores every book above six (overtricks)yesyes, no
No-trump bids score double (noTrumpDouble)yesyes, no

12 cards each and a 6-card kitty. The auction goes once around the table, each bid strictly higher than the last (levels up to 7; at the same level no-trump outranks a suit bid). If the other three pass, the dealer must bid. The winner names trump (high or low) or, for no-trump, high or low; takes the kitty; and discards six cards. In low play the ace is best and the king is weakest. Jokers outrank all trump in a suit contract; in no-trump a joker never wins a trick. A team makes the contract with at least 6 plus the bid level books, where the kitty counts as one book for the declarers. Only the declaring team's score moves: made scores books minus six (overtricks on) or the bid level (off); failed loses the bid level; no-trump doubles either way when that option is on. The game ends when the declaring team reaches +7, or when it falls to -7 (the other team wins).

The Tonk and Bid Whist scoring above, and the Spades bag rules, are the code's own definitions. Other households play different point values and end conditions; the options only cover the switches listed.

How your body moves

  • Walking. You are an upright body 0.3 m in radius. Speed eases up and down (walk 2.2 m/s and run 4 m/s on a desktop, 1.8 and 3.2 in VR). Anything up to 0.3 m high is stepped onto.
  • Jumping. A jump rises about 0.85 m and lasts about 0.7 s, one per press. You land on flat tops up to about 0.8 m (benches, sofas, the pool steps) and clear low things; counters, the grill, the music booth and card tables stay out of reach. The take-off speed carries, so a running jump goes farther, and the stick only steers a little in the air. A press up to 0.1 s before landing, or up to 0.1 s after walking off an edge, still jumps.
  • The pool. In the deep end you float with your eyes 0.25 m above the water, at half speed, and cannot jump out: swim to the shallow end and walk out up the steps. Going in makes a splash.
  • Teleport. It lands only on ground-level surfaces (the floor, or what you could step onto from it), within 7 m and with no wall between. Otherwise the aim turns red with its word, Too far, Blocked or Too deep, and letting go does nothing.
  • Other things. Other players are never solid. Card tables, their chairs and the dealer stands always block.

7. Original design decisions and cultural direction

Everything is made in this project. All visuals are procedural geometry (boxes, cylinders, balls, cones) and canvas-drawn art. The two gallery artworks are generated from fixed seeds in client/src/world/art.ts: abstract shapes, no figures, faces, text or copied images. The music is an original WebAudio groove written in code (client/src/world/Music.ts), one feel per theme (about 92 beats a minute with a swing for the day, 112 for the night). Fonts are the system fonts. The client folder holds no images, audio files or fonts; its only assets are two small controller-profile files so the app does not fetch models from a CDN. No third-party art, audio, fonts or brand marks are used.

What the spaces are meant to evoke. The aim is the feel of a family gathering and a house party, described only by what is built:

  • A cookout patio with a grill and smoker barrel, picnic table and string lights.
  • A potluck kitchen where "everybody brought something": a counter lined with covered dishes, and a round family table.
  • A music corner with a booth, speakers and a dance floor.
  • Card-table lounges, one for each of Tonk, Spades and Bid Whist, with sofas, lamps and shelves, so the games sit alongside the rest of the party rather than apart from it.
  • The "gathering" artwork shows rings of seats around a shared table; the "rhythm" artwork is a patchwork crossed by a line of beats, for the music corner.

Spades, Bid Whist and Tonk are treated as house-party games people play together. Other people appear as a plain capsule body with a nose showing which way they face and a name plate; nothing is drawn to stand for any group of people. House rules are explicit settings because families play these games differently.

10. Checks to do in a real headset

No physical headset was used to build or test this app. The browser tests drive an emulated headset (the iwer WebXR emulator in node_modules: a Meta Quest 3 with two Touch Plus controllers, or tracked hands). They show what the code does with each button, stick and pose, read back from the server and from the app's own test hooks. They cannot show how any of it feels. A person with a headset should do the steps below with both controllers, in order, and note the number of any step that does not do what it says.

Before you start: join a room on the headset (section 2, "Headset on the same network") and press Enter VR. Keep the default settings: Walk and teleport, snap turn, vignette, jumping, vibration and sound effects on, right hand as main hand.

Cards

  1. Walk to Tonk Table 1. Point the right trigger at the marker of a free chair and pull it. You sit, at seated eye height, facing the table.
  2. Point the left trigger at Ready and pull; then the right trigger at Start. Each press gives a buzz in the hand that pressed, and the game starts with bots in the other seats.
  3. On your draw, put your left hand on the stock pile, squeeze the grip, pull the hand toward you and let go. A faint buzz when the hand reaches the pile, a firmer one on the squeeze, a strong one when you let go; a card is added to your hand. All in the left hand only.
  4. Squeeze the left grip on a card in your hand. The card stays where it lay and grows a little; it does not jump. Moved, it follows the hand with no lag and no wobble and keeps its face to you.
  5. Carry it over the discard pile and let go. The zone under the card thickens and says what letting go will do; letting go discards it, with a strong buzz in the left hand.
  6. On your next turn, do steps 3 to 5 with the right hand. The same, felt only in the right hand.
  7. From arm's length, point the right trigger at a card in your hand and hold it. After about a quarter of a second the card glides to about 25 cm in front of that hand. Carry it over the discard pile (on Spades, the felt in the middle) and let go. It is placed. Do the same with the left trigger.
  8. Both hands at once: take one card with the left grip and lift it toward you, then take another with the right grip. Each hand holds its own card; moving one hand moves only its card. Let go of the left card away from the table. It goes back to your hand; the right hand still holds its card.
  9. With the right grip on a card and its ray pointing at a token, squeeze grip and trigger at the same moment. One grab of the card (one buzz); the token is not pressed.
  10. Carry a card off the table, to your chest or to the side, and let go. It glides back into your hand with a refuse buzz; nothing is played.
  11. Carry a card over the discard pile and press B before letting go. It goes back to your hand; nothing is discarded, also when you then let go of the grip.
  12. A controller going to sleep: carry a card over the discard pile with the left grip, then, still squeezing, take out the left controller's battery (or put it down out of view until it sleeps). The card goes back to your hand and is not discarded. The right hand can then take it and discard it. When the left controller is back, it takes cards as before.
  13. Hold a card with the left grip and snap-turn with the right stick. The card stays in your hand through the turn.
  14. Still seated, push the left stick, click it, press A, and push the right stick forward. Nothing moves: no walking, running, jump or teleport arc. The right stick left and right turns; clicking either stick faces the table again.

Moving

  1. Leave the table (X, then Leave table). Push the left stick forward. You walk the way you are looking, starting smoothly; the edges of the view darken while you move.
  2. While walking, click the left stick. You run. Letting the stick back to rest ends the run.
  3. Take a real step forward, then walk into the foyer bench. You stop with your head (not the middle of your play space) against the bench. Keep pushing and press A. You jump onto the seat and stay at its height, with a buzz in the right hand on landing. Later, take a real step into a wall. The view stops at the wall and never goes through it.
  4. Walk off the front of the bench. You drop back to the floor.
  5. Run across the foyer and press A. You land clearly farther than from a walking jump; the stick only nudges you in the air.
  6. Walk from the deck into the deep end of the pool. A splash; you float with your eyes just above the water and move at half speed; A does not lift you out. Swim to the shallow end and walk up the steps. You are back on the deck.
  7. Push the right stick forward over open floor. A green arc from your right hand ends in a ring. Let go. A short blink, and you stand on the ring, with a buzz in the right hand.
  8. Aim at a spot behind a wall, or at a bench seat. The arc turns red with a cross and the word Blocked. Let go. You stay, with a refuse buzz.
  9. Aim again and press B. The arc goes; letting go of the stick does nothing. Teleport, then push the stick forward again at once. The new arc only appears after a short pause (a quarter of a second).

Comfort settings

X opens the VR menu. Press a setting with either hand's trigger; press each one again afterwards to put it back.

  1. Vignette off. Walking and smooth turning no longer darken the edges.
  2. Turn: smooth. The right stick turns smoothly. Turn: snap. It turns in 30-degree steps, one per push.
  3. Move: teleport only. The left stick no longer walks; pushed forward it aims a teleport from the left hand.
  4. Jumping off. A does nothing.
  5. Vibration off. No buzz on hover, grab, place, landing or refusal; the sounds still play.
  6. Reduce motion is in the page's Settings (Menu, Settings) before you enter VR. Cards go to their places at once instead of gliding, a card taken with the trigger is in the hand at once, and the fireworks stand still.

Tracked hands

  1. Put the controllers down and hold up your hands. Point at the Menu button beside you and pinch, with the left hand and then the right. The menu opens and closes; a pinch on a setting changes it.
  2. At a table, pinch a card in your hand with your fingertips on it and move. The card follows the pinching hand; let go over a drop zone, it is placed; elsewhere, it goes back. There is no buzz.

What the automated tests already cover

In an emulated headset (tests/e2e/xr.e2e.ts, xr-hands.e2e.ts, xr-move.e2e.ts), each move checked against what the server says and what each hand holds:

  • Grabbing with the left grip and with the right, and placing on the felt (Spades) and the discard pile (Tonk). The card does not jump when taken, stays within a millimetre of the hand while held, and turns with the hand in the same frame during a snap turn.
  • A far grab with each trigger: the card comes to 25 to 35 cm from the grip and is played on release.
  • Grip and trigger together: one grab, the token under the ray not pressed, nothing sent.
  • Two cards held at once: each moves only with its own hand, and letting go of one leaves the other held.
  • Letting go away from the table, and B: the card goes back and nothing is sent, also after the grip is let go.
  • A controller switched off while carrying over the discard pile: the card goes back, nothing is discarded, the other hand then discards it, and the switched-off controller works again when it returns.
  • Every hover, grab, place, refuse and landing cue, and every buzz sent to the emulator, goes to the hand that acted, never the other.
  • Walking (about 1.8 m/s, no jumps in position), running (about 3.2 m/s) and stopping; the body stopping against the bench at the head's place after a real step; a jump onto the bench that stays at 0.45 m and peaks between 0.8 and 0.9 m; walking off it to the floor.
  • Teleport aimed by the turn stick and landing on the mark; a wall refusing; the quarter-second pause before the next aim; B ending an aim; Teleport only making the move stick aim and stopping walking; jumping off; vibration off; a seat where no movement control moves the player while turning and recentring still work.
  • Pressing with either hand: the ready, start and bid tokens by either trigger; the VR menu opened and closed by either trigger and by X, and its Move, Jumping and Vibration buttons by either trigger; with tracked hands in place of the controllers, the menu and its Turn button by either hand's pinch.

What only a headset can show

The emulator (iwer 2.8) has both grips, triggers, sticks and buttons, switching a controller off, and tracked hands with a pinch. What it does not have is a body: its vibration motors accept every buzz and feel nothing (the tests record which controller each buzz went to and how strong it was asked to be), its poses are exact, and here it draws about 15 frames a second.

  • Latency and jitter. The emulator draws about 15 frames a second on software graphics and its poses are perfectly still; a real headset runs at 72 to 120 frames a second with real tracking noise.
  • Comfort. Walking and running speeds, the ease in and out, the vignette, the teleport blink, snap and smooth turning, and the jump height, as felt by a person.
  • Vibration strength. The tests see which controller each buzz is sent to and how strong it is asked to be, not what the hand feels.
  • Reach. Whether every card, pile and token is in comfortable reach seated and standing, and whether the grab range (9 cm from a controller's grip, 7 cm from a fingertip) feels right.
  • Real controllers. A controller that really sleeps or loses tracking, real buttons and sticks (rest positions, drift), and tracked hands with real fingers. The tests never grab a card with a tracked hand's pinch: the emulator's hand joints were not driven onto a card.
